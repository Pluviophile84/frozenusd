# Frozen USD — website

**Frozen. Still moving.**

The production website for Frozen USD ($FUSD), a memecoin parody presented as a financial product: the dollar that trades frozen. It is a single editorial homepage plus a 404 page, built as a static Astro site and deployed by Vercel from GitHub.

Frozen USD is not a dollar-backed product, a redemption service or a way to unlock frozen USDT or USDC. The site says so in the token facts, FAQ and footer.

## Commands

Requires Node.js 24.x (see `.nvmrc`) and npm.

```bash
npm ci
```

```bash
npm run dev       # local dev server at http://localhost:4321
```

```bash
npm run check     # Astro + TypeScript diagnostics (astro check, tsc --noEmit)
```

```bash
npm run build     # static production build into dist/
```

```bash
npm run preview   # serve the production build locally
```

```bash
npm test          # config, brand and browser tests (builds the site itself)
```

```bash
npm run assets    # regenerate posters + Open Graph image (only after changing them)
```

`npm test` drives Playwright's Chromium. If it is not installed on your machine, run `npx playwright install chromium` once.

## Vercel settings

Import this repository in Vercel (**Add New → Project → Import Git Repository**) with:

| Setting | Value |
|---|---|
| Framework preset | Astro |
| Root directory | `./` (repository root) |
| Install command | `npm ci` |
| Build command | `npm run build` |
| Output directory | `dist` |
| Node.js version | 24.x (also declared in `package.json` `engines`) |
| Environment variables | None required |

There is no `vercel.json`: Astro's static output needs no extra configuration, and Vercel serves `dist/404.html` for unknown routes. There are no SPA rewrites. Every push to a branch gets a preview deployment; merges to the production branch deploy production. Vercel's own Git integration is the only deployment path (the GitHub Actions workflow in `.github/workflows/ci.yml` only runs checks and tests).

Previews are always `noindex`. A production deployment becomes indexable only after launch with a verified `canonicalOrigin` (see below).

## Launch: pre-launch → live

All launch values live in **`src/config/site.ts`**. The committed state is pre-launch: no contract address, no trading link, no social links, `noindex`.

At launch, edit these fields with real, verified values:

```ts
canonicalOrigin: 'https://<your production domain>',   // optional but needed for indexing
token: {
  status: 'live',
  network: 'solana',                 // pump.fun tokens are on Solana
  contractAddress: '<real mint address>',
  tradeUrl: 'https://<real trading page>',
  explorerUrl: 'https://<explorer page for that exact address>',
},
social: {
  xUrl: 'https://x.com/<official handle>',          // or keep null
  communityUrl: 'https://<official community>',      // or keep null
},
```

Then commit and push. **The site is static, so the change only appears after Vercel rebuilds and redeploys.** Step-by-step instructions are in [`docs/launch-checklist.md`](docs/launch-checklist.md).

The build refuses an incomplete or malformed live configuration (missing network, a placeholder or wrongly formatted address, a non-HTTPS or example URL, an explorer link for a different address) with an error naming each problem. Address checks are syntax only. They do not prove the token exists or what permissions it has; verify those separately.

## What was tested

`npm test` runs 43 tests:

- **Configuration rules:** the committed config is pre-launch; a valid live fixture resolves; 13 kinds of invalid live configuration are rejected; placeholder/example/non-HTTPS URLs are never accepted; address syntax per network.
- **Brand integrity:** the official logo package matches its SHA256SUMS; shipped logo files are byte-identical to the originals; the inline emblem path is the official geometry; posters embed the official path and need no font.
- **Browser, pre-launch build:** no copy button, trading link or social link; every internal anchor resolves and the only external link is the dated Binance source; no broken images, failed requests or console errors; `noindex`, no canonical, no sitemap; all six downloads return real files (PNG checked at 1080×1350); keyboard mobile menu (expanded state, Escape, focus return); identity, promise, CTA and contract status all within the first 390×844 screen; keyboard FAQ; Frozen USD / $FUSD branding; smooth footer and logo navigation (including repeated clicks and keyboard activation), immediate navigation for reduced motion, correct sticky-header offsets; motion runs, pauses, and is removed for reduced motion; content, navigation and FAQ without JavaScript; real 404 status and page.
- **Browser, live fixture build:** Buy, address, Copy and Explorer controls appear with the configured values; copying puts the exact address on the clipboard and announces success; a refused clipboard announces failure; live production build emits canonical, `index`, OG image and a sitemap on the configured origin.
- **Invalid live fixture:** the build fails with a clear configuration error.

Test fixtures exist only in `tests/helpers/fixtures.mjs`; they are never written to `src/config/site.ts`.

Historical baseline before the $FUSD visual refinement, measured with Lighthouse 13.6 (simulated throttling, not field data): mobile performance 99, accessibility 100, best practices 100, LCP 1.5 s, CLS 0, TBT 10 ms, 143 KiB transferred. SEO scores 66 only because pre-launch pages are deliberately `noindex`.

## Not yet connected

- **Token launch values:** the contract, network, trading and explorer links do not exist yet. They stay `null` until launch.
- **Official social accounts:** `xUrl` and `communityUrl` are `null`; the related actions stay hidden until they are set.
- **Production domain:** `canonicalOrigin` is `null`, so no canonical URL or sitemap is produced. Open Graph tags use the URL Vercel assigns to each deployment.
- **Vercel project:** the repository uses Vercel's Git integration. Branch previews can be reviewed before merging to the configured production branch.
